# AI Evidence Extractor for Windows

This is a Windows desktop app for the existing video evidence triage project. The packaged executable opens the existing Gradio interface in a native WebView2 window and does not open a separate browser or terminal. The one-folder distribution includes the Python runtime and application dependencies; WebView2 Runtime is required on Windows. The app includes persistent, unlimited analysis history with case metadata, notes, detections, object tracks, evidence captures, CAM heatmaps, summaries, highlights, and reports. The history index is stored in `%LOCALAPPDATA%\AI Evidence Extractor\analysis_history.json`; generated per-analysis files are stored in `%LOCALAPPDATA%\AI Evidence Extractor\outputs\history`. Original videos are referenced by their source paths and are not copied into History. The app icon is a custom creative spark mark.

## Install and first launch

For a direct launch, run `dist\AI Evidence Extractor\AI Evidence Extractor.exe`; it works independently of the current working directory and does not require a `.lnk` shortcut. To create an installer, build `AI_Evidence_Extractor_Setup.exe` with the steps below, run it, and optionally use the shortcut it creates. The app runs using its packaged Python runtime and dependencies; it does not require a separate Python installation. The installer downloads and verifies Microsoft's signed x64 Visual C++ Runtime and WebView2 bootstrapper, then installs missing prerequisites before the app can be launched. Setup requests administrator permission to install the system runtime. A GitHub "Source code" archive is source code only and is not a runnable app package. The first launch needs internet access to download any missing AI model weights from their original Hugging Face repositories into `%LOCALAPPDATA%\AI Evidence Extractor\models`.

The app runs locally on your computer and does not create a public Gradio share link. The Ensemble Configuration panel shows the actual inference device and precision. The desktop installer currently supplies CPU-only PyTorch, so it uses the CPU even if an NVIDIA GPU is installed. CUDA is selected automatically only when a separate, compatible CUDA-enabled runtime is installed as `%LOCALAPPDATA%\AI Evidence Extractor\runtimeenv_cuda2` with its `.aee_cuda_ready` marker. Installing a CUDA driver alone or changing the device setting cannot turn a CPU-only PyTorch build into a GPU build. Keep the current runtime as a fallback and validate the CUDA runtime against the exact installed NVIDIA driver and GPU before marking it ready.

To keep detection results consistent, analysis uses the same models, input frames, confidence thresholds, and full-precision CPU inference or CUDA FP16 setting already selected by the runtime. The video decoder now prefetches at most four frames on a background thread while inference processes earlier frames in order; it does not skip or parallelize inference frames. A modern NVIDIA GPU with enough VRAM is the largest hardware upgrade for this multi-model workload. A fast SSD helps when reading large source videos and writing evidence files; additional CPU cores can help decoding and preprocessing, while system RAM should be sufficient for the video resolution and model ensemble.

Video object detection samples at 1 fps (one frame every second) to reduce analysis time. Audio analysis and output-video merging continue to use their own sampling and frame-rate settings. Object IDs are associated across sampled frames using detection overlap and position.

For challenging footage, select **Enhanced accuracy (slower)** before analysis to enable test-time augmentation on supported PyTorch detectors. This can improve detection robustness, especially for small or difficult objects, at the cost of longer analysis. It is off by default so normal analysis speed is unchanged. Validate any accuracy changes against a labeled set using `evaluation.py` before relying on them.

FFmpeg is installed as a Python package dependency and added to the process path at startup. User files and generated app data are stored under `%LOCALAPPDATA%\AI Evidence Extractor` and the operating system temporary folder.

The left-side menu contains **Account**, **Detailed History**, **Updates**, **About Us**, and **Contact Us**. Account opens profile details and account security. History remains a workspace tab with a simple analysis summary table. Detailed History opens in its own full-screen, scrollable archive window. Analyses appear newest-first, each with **Details**, **Download ZIP**, and **Remove** actions; Details opens its captures, reports, detection records, and object tracks below the list. Removing an analysis deletes its history record and only its generated per-video artifacts from app-managed storage; original source videos are never deleted, and shared run reports are retained while another analysis from that run remains. The archive also offers a ZIP download of all history. ZIP exports contain generated analysis artifacts and metadata, not copies of original videos. The top-right toolbar shows **Update the app** to the left of the theme control only when a newer release is available; selecting it opens the update center. Guests can save a local display name and photo or sign in with Google; signed-in users can log out and manage their profile. The app checks the HTTPS release feed on startup and from the Updates page. **Download Update** verifies and stages the update package with a visible progress bar; **Install Update** applies it internally and reports file-by-file progress in the Updates window. No setup file is opened. Restart the app when prompted to load the new version. The setup installer remains available for first installs and recovery. See [UPDATE_RELEASES.md](UPDATE_RELEASES.md) for publishing releases and connecting the update feed.

The app requires an email/password account, Google sign-in, or an explicit guest-mode choice before opening the workspace. That choice is remembered between launches. Guest profile names and photos are stored only on this computer; signed-in profile data is stored in a connected Supabase project. Source videos, analysis history, reports, and results remain local. Configure accounts using [SUPABASE_SETUP.md](SUPABASE_SETUP.md).

## Build the application and installer

1. Install the project dependencies from `requirements.txt` in the build Python environment, plus PyInstaller. Building the installer also needs internet access to download and verify Microsoft's Visual C++ Runtime and WebView2 installers.
2. Run `build_windows.ps1` from PowerShell. It creates the one-folder application using `AI Evidence Extractor.spec`.
3. The standalone executable is written to `dist\AI Evidence Extractor\AI Evidence Extractor.exe`. The script also creates the installer and in-app update archive; Inno Setup 6 or 7 is required for the installer step.

The installer places the packaged application files in the selected install directory and creates shortcuts that target the executable directly. Model weights remain external mutable data and are fetched during first launch. For a controlled academic release, pin and archive the exact model revisions before distributing.

## Project evaluation

Use `evaluation.py` and `EVALUATION_PROTOCOL.md` to score detections against manually labeled videos. Automated detections, threat scores, and EigenCAM are review aids and require human verification.
