# AI Evidence Extractor for Windows

This is a Windows desktop app for the existing video evidence triage project. The packaged executable opens the existing Gradio interface in a native WebView2 window and does not open a separate browser or terminal. The one-folder distribution includes the Python runtime and application dependencies; WebView2 Runtime is required on Windows. The app includes persistent, unlimited analysis history with case metadata, notes, detections, object tracks, evidence captures, CAM heatmaps, summaries, highlights, and reports. The history index is stored in `%LOCALAPPDATA%\AI Evidence Extractor\analysis_history.json`; generated per-analysis files are stored in `%LOCALAPPDATA%\AI Evidence Extractor\outputs\history`. Original videos are referenced by their source paths and are not copied into History. The app icon is a custom creative spark mark.

## Install and first launch

For a direct launch, run `dist\AI Evidence Extractor\AI Evidence Extractor.exe`; it works independently of the current working directory and does not require a `.lnk` shortcut. To create an installer, build `AI_Evidence_Extractor_Setup.exe` with the steps below, run it, and optionally use the shortcut it creates. The app runs using its packaged Python runtime and dependencies; it does not require a separate Python installation. The installer downloads and verifies Microsoft's signed x64 Visual C++ Runtime and WebView2 bootstrapper, then installs missing prerequisites before the app can be launched. Setup requests administrator permission to install the system runtime. A GitHub "Source code" archive is source code only and is not a runnable app package. The first launch needs internet access to download any missing AI model weights from their original Hugging Face repositories into `%LOCALAPPDATA%\AI Evidence Extractor\models`.

The app runs locally on your computer and does not create a public Gradio share link. The Ensemble Configuration panel and live-camera status show the actual inference device and precision. The installer uses CPU-only PyTorch by default for broad compatibility. On an NVIDIA-equipped PC, the desktop app automatically checks the driver and connects the GPU on first launch by creating an isolated CUDA runtime, downloading pinned PyTorch packages, and verifying the live-detection checkpoint before restarting into GPU mode. This one-time setup requires internet access and downloads several gigabytes. If GPU setup fails, the app continues in CPU mode and offers a retry; the live status reports the device actually used.

After sign-in, choose **In Real-Time Detection** for webcam screening or **Upload Your Videos to Detection** to open the existing analysis workspace. The real-time view uses the supplied seven-class model and draws labeled, color-coded bounding boxes with confidence scores on detected objects. New installers bundle its weights; an existing installation downloads them on first use from the HTTPS GitHub release and verifies the pinned SHA-256 before loading. Webcam frames are processed in memory and are not added to analysis history. Detection scores and boxes are an investigative aid, not proof; independently review the original footage. The checkpoint's embedded metadata identifies its license as AGPL-3.0; see [MODEL_LICENSES.md](MODEL_LICENSES.md).

Real-time detection uses the user-supplied `best (2).zip` checkpoint, verified against the bundled `assets/realtime_weapons.pt` SHA-256, with a continuous browser webcam preview and a separate viewport-level overlay. The overlay aligns boxes to mirrored webcam video without mirroring the labels and tracks resize and scroll. **Enable live camera** grants camera access and starts streaming; the underlying Gradio record/stop controls are hidden, and leaving the live-detection route stops frame streaming. **Fast · 512 px** is the default to reduce inference work; choose **Balanced · 640 px** for more image detail. Adjust the **Detection sensitivity** slider (0.10–0.75, default 0.25): lower values surface more candidates but can increase false positives. When there are no detections, the live status suggests adjusting sensitivity or switching to Balanced mode. The live status identifies CPU or the connected GPU and precision. When the CUDA runtime is installed, inference explicitly uses CUDA and FP16 where supported. Webcam frames are RGB and are converted to BGR for Ultralytics inference. Frames are sampled every 0.05 seconds and processed one at a time; Gradio's latest-frame queue policy drops stale work when inference falls behind. The 50 ms sampling interval is not a promise of 50 ms inference, and 0.5 ms detection updates are not achievable; box refresh depends on model and hardware speed. Detector box tensors are transferred to CPU in one batch and each frame is capped at 20 detections to reduce processing overhead. These are general settings, not a validated optimum for every scene. Ultralytics recommends validating settings on representative labeled footage: [prediction arguments](https://docs.ultralytics.com/modes/predict/#inference-arguments), [validation guidance](https://docs.ultralytics.com/modes/val/).

Standard analysis is optimized for speed: it loads and runs the two smallest enabled detectors at 512 pixels. **Enhanced accuracy (slower)** loads/runs all enabled detectors at the configured 640-pixel input and enables test-time augmentation. The fast profile uses fewer models and a smaller input, so it may miss detections that the full ensemble finds; review important footage in both modes. Model loading is deferred for detectors not used by the fast profile, reducing startup memory and inference work. Inference uses full precision on CPU or CUDA FP16 when available. The video decoder prefetches at most four frames on a background thread while inference processes earlier frames in order.

The bundled checkpoints are YOLO models; a generic pretrained RT-DETR checkpoint is not a weapon detector. To use a weapon-trained RT-DETR checkpoint, place the checkpoint in `%LOCALAPPDATA%\AI Evidence Extractor\models` and add a model entry to `ensemble_manifest.json` with its relative `path`, `name`, confidence `conf`, and `"backend": "rtdetr"`. Existing manifest entries without `backend` continue to use YOLO. Do not substitute generic COCO weights for firearm detection. A modern NVIDIA GPU with enough VRAM is the largest hardware upgrade for this multi-model workload. A fast SSD helps when reading large source videos and writing evidence files; additional CPU cores can help decoding and preprocessing, while system RAM should be sufficient for the video resolution and model ensemble.

Video object detection samples at 1 fps by default. Choose **Fast · 0.5 samples/sec** in the analysis controls to run inference and explainability on half as many frames; this can reduce analysis time, but may miss brief events. The selected mode and sampling rate are recorded with each analysis. Audio analysis and output-video merging continue to use their own sampling and frame-rate settings. Object IDs are associated across sampled frames using detection overlap and position. Live progress updates are also throttled to reduce repeated dashboard rendering without changing detection results.

For challenging footage, select **Enhanced accuracy (slower)** before analysis to run the full enabled ensemble with test-time augmentation on supported PyTorch detectors. This can improve detection robustness, especially for small or difficult objects, at the cost of longer analysis. It is off by default. Validate any accuracy changes against a labeled set using `evaluation.py` before relying on them.

FFmpeg is installed as a Python package dependency and added to the process path at startup. User files and generated app data are stored under `%LOCALAPPDATA%\AI Evidence Extractor` and the operating system temporary folder.

The left-side menu contains **Account**, **Detailed History**, **Updates**, **About Us**, **Contact Us**, and **Feedback & Support**. Account opens profile details and account security. History remains a workspace tab with a simple analysis summary table. Detailed History opens in its own full-screen, scrollable archive window. Analyses appear newest-first, each with **Details**, **Download ZIP**, and **Remove** actions; Details opens its captures, reports, detection records, and object tracks below the list. Removing an analysis deletes its history record and only its generated per-video artifacts from app-managed storage; original source videos are never deleted, and shared run reports are retained while another analysis from that run remains. The archive also offers a ZIP download of all history. ZIP exports contain generated analysis artifacts and metadata, not copies of original videos. **Feedback & Support** requires a signed-in app account and saves categorized messages and optional PNG/JPG/WebP screenshots (up to 5 MB) locally under `%LOCALAPPDATA%\AI Evidence Extractor\feedback`; submissions are not uploaded or emailed. The top-right toolbar shows **Update the app** to the left of the theme control only when a newer release is available; selecting it opens the update center. Guests can save a local display name and photo or sign in with Google; signed-in users can log out and manage their profile. The app checks the HTTPS release feed on startup and from the Updates page. **Download Update** verifies and stages the update package with a visible progress bar; **Install Update** applies it internally and reports file-by-file progress in the Updates window. No setup file is opened. Restart the app when prompted to load the new version. The setup installer remains available for first installs and recovery. See [UPDATE_RELEASES.md](UPDATE_RELEASES.md) for publishing releases and connecting the update feed.

The app requires an email/password account, Google sign-in, or an explicit guest-mode choice before opening the workspace. That choice is remembered between launches. The public project connection in `account_defaults.json` is included in release installers, so users on a new computer can choose **Continue with Google** without configuring Supabase. In-app updates carry the same public settings inside the existing `update_config.json` file so older updater versions accept the package. The Google button remains visible if defaults are missing, and **Connection setup** below the sign-in form can be used to connect it manually. Guest profile names and photos are stored only on this computer; signed-in profile data is stored in a connected Supabase project. Source videos, analysis history, reports, and results remain local. Configure accounts using [SUPABASE_SETUP.md](SUPABASE_SETUP.md).

## Build the application and installer

1. Install the project dependencies from `requirements.txt` in the build Python environment, plus PyInstaller. Building the installer also needs internet access to download and verify Microsoft's Visual C++ Runtime and WebView2 installers.
2. The checked-in `account_defaults.json` supplies the public Supabase project URL and publishable key for release builds. The file contains public client values, not secrets. Local builds can optionally override them in the PowerShell session:

   ```powershell
   $env:AEE_SUPABASE_URL = 'https://your-project.supabase.co'
   $env:AEE_SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_...'
   .\build_windows.ps1
   ```

   The build includes the configured connection by default. An override uses a temporary config file which is removed afterward. Never use a `service_role` or secret key. If the defaults file is absent, users must configure the connection themselves on each computer. If only one override variable is set, the build stops.

3. The script creates the one-folder application using `AI Evidence Extractor.spec`.
4. The standalone executable is written to `dist\AI Evidence Extractor\AI Evidence Extractor.exe`. The script also creates the installer and in-app update archive; Inno Setup 6 or 7 is required for the installer step.

The installer places the packaged application files in the selected install directory and creates shortcuts that target the executable directly. Model weights remain external mutable data and are fetched during first launch. For a controlled academic release, pin and archive the exact model revisions before distributing.

## Project evaluation

Use `evaluation.py` and `EVALUATION_PROTOCOL.md` to score detections against manually labeled videos. Automated detections, threat scores, and EigenCAM are review aids and require human verification.
